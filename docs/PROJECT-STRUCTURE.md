# SecureAccess / RBAC-SYSTEM project map

## Areas

- `web/` is the main Next.js App Router application. It uses React, TypeScript,
  Node.js, and MongoDB. Its local environment file and Git repository remain
  inside this directory.
- `coursework/cpp-oop/` contains the separate C++ object-oriented RBAC exercise,
  its CMake configuration, SQLite amalgamation (`include/sqlite3.h` and
  `src/sqlite3.c`), and its original root-working-directory database at
  `rbac.db`.
- `coursework/cpp-oop/archive/rbac-build.db` preserves the distinct database
  that was previously inside the old root `build/` directory. It is retained as
  data, not used by the CMake target by default.
- `coursework/static-frontend-demo/` contains the standalone HTML, CSS, and
  JavaScript login/dashboard demonstration. It is separate from `web/`.
- `docs/` holds project and OOP review notes.

There are no Java source or class files in the inspected workspace.

## Run the web application

From the repository workspace:

```powershell
cd web
npm run dev
```

Open `http://localhost:3000`. The MongoDB connection is configured locally in
`web/.env.local`; keep that file private and do not add its values to source
control.

## Build and run the C++ coursework

From the repository workspace, configure and build with CMake and Ninja:

```powershell
cmake -S coursework/cpp-oop -B coursework/cpp-oop/build -G Ninja
cmake --build coursework/cpp-oop/build
```

Run the program from its project directory so the existing relative database
path continues to resolve to `coursework/cpp-oop/rbac.db`:

```powershell
Push-Location coursework/cpp-oop
try { .\build\rbac.exe } finally { Pop-Location }
```

The application opens `rbac.db` relative to its current working directory.
Keep the working directory as shown to avoid opening or creating a different
database.

## Generated outputs

`coursework/cpp-oop/build/` is generated by CMake and can be recreated from the
preserved C++ sources and CMake configuration. Keep the two SQLite databases;
they contain different data. The original root executables and old root build
outputs are retained separately during this cleanup for recovery until the
new build and database smoke check complete.
